Lua-Studio – Manual

Version 0.7.3 · 21 Nov 2026 · Deutsche Anleitung: «Lua-Studio - Anleitung»

1. What is Lua-Studio?

Lua-Studio is a program for Mac and Windows that belongs to our Ethos Luas (Electric, Heli, Jet, Glider, Gas Engine). Radio live: your FrSky radio's display appears on the computer and you operate the radio with mouse and keyboard, over a USB cable in the radio's serial mode.

Models (from 0.2.0, chapter 6): set up boxes, limits and settings per model on the computer and transfer them to the radio. Later: analyse flights.

Picture taken with the Ethos simulator.

2. What you need

  • FrSky radio with Ethos 26.2 or newer and a colour display. Tested on real hardware: X18RS.
  • Mac (Apple silicon or Intel) or Windows PC (64-bit), USB data cable.
  • The matching file from the GitHub release (“Releases” on the right of the repository page):
    • Mac with Apple silicon: Lua-Studio-0.7.3-mac-arm64.dmg
    • Mac with Intel: Lua-Studio-0.7.3-mac-x64.dmg
    • Windows: Lua-Studio-0.7.3-win-x64.exe

«Radio live» only reads the display and sends keys and touches, the same as operating the radio by hand. «Models» only writes to the folder scripts/studio on the radio and backs up the old files on the PC first. Lua-Studio never changes models themselves.

3. Install

Mac

  1. Double-click the DMG file and drag Lua-Studio into Applications.
  2. Open Lua-Studio. The program is not registered with Apple, so the first time macOS says it cannot verify the developer. Then go to System Settings › Privacy & Security, click Open Anyway next to “Lua-Studio was blocked” and confirm. On older macOS versions, right-click the app › Open is enough.

Windows

  1. Put the EXE file in a fixed place (e.g. Documents) and double-click it. There is no installer.
  2. If “Windows protected your PC” appears: More info › Run anyway.
  3. The first start takes 5–10 seconds because the program unpacks itself first.

4. Connect the radio

  1. Switch the radio on and connect it to the computer with the USB cable.
  2. The radio asks for the USB mode. Choose Serial (not drive/storage).
  3. In Lua-Studio, choose the radio under Connection at the top. Ethos radios are marked with ● and are selected automatically. If it says “No radio found”: check cable and mode, then click Search again.
  4. Click Connect. The status line shows “Please allow remote control on the radio”.
  5. Confirm the remote control prompt on the radio. Lua-Studio waits up to 2 minutes.
  6. The status line shows Connected, the radio and the Ethos version. The display appears shortly after.
Every new connection has to be allowed on the radio again, also after disconnecting and reconnecting.

6. Setting up models (tab «Models»)

Here you set up per model what the Lua shows on the radio: boxes, limits and settings. This works for the Luas with studio support (Electric, Heli, Jet, Glider, Gas Engine ECU and Gas Engine Carb; until 21 Nov 2026 called Elektro, Heli RF, Segler, Motoren ECU and Motoren Vergaser). The radio does not recalculate anything; it only reads the finished, checked file.

While no model is open, the tab shows two entry points (from 0.4.0): Set up with the radio (loads the connected radio's models or leads to the connection) and Prepare without a radio with the list of prepared models (clickable). The + Prepare button at the top next to the tabs opens the prepare form from anywhere.

Load models

  1. Load the model once on the radio so the Lua writes its info file (model name, window sizes, sensors).
  2. Choose the Source: Connected radio (connect in the «Radio live» tab first), SD drive (radio in drive/storage mode) or Folder (export).
  3. Click Load models and pick the model in the list.

Layout

  • View selects the window size (e.g. 784 × 316 compact or 800 × 480 full screen). The size the Lua last ran in on the radio is marked with ● and «last shown on the radio» and is preselected when you open a model. Only changes in this view show up on the radio right away.
  • Drag a box to move it, the bottom right corner resizes it. Add box and Remove box (or the Delete key). At most 16 boxes per view.
  • On the right for the selected box: value (Lua values, own sensors, channels), display (number, ring/gauge, bar horizontal/vertical, curve, status text), label, range, colours for normal/warning/alarm/background, up to 3 colour steps (colour only) and extra line (minimum, maximum, average).
  • A red frame marks a box that is outside the edge, too small, overlaps another or lies on an area the Lua draws itself (grey hatched, e.g. the status bar). The radio discards boxes that are too small or outside the edge; overlapping ones end up underneath.
  • At the top right you see how much space the settings need (entries, at most 1100).
  • The studio draws the preview itself. It shows position, size and type; fonts and details only show on the radio (check with «Radio live» afterwards).
  • Preview like the Lua (from 0.6.0, Electric first): the preview draws boxes, top bar and the «Flights» field the way Electric draws them on the radio (colours, sizes, extra line MAX/MIN). It shows example values; the font is close to Ethos. The template Original (like the Lua) sets the layout and colours of the built-in display for all display sizes. Not adjustable via the studio file (Electric 0.6.1 draws them only in its built-in display): footers like «6S 23.1V», «at 46 A», «0.6 Wh», the «AUF 0» button (reset), the colour stripes on top of the boxes and titles that follow the language of the radio. The template hint lists the same. From 0.7.0 also for Jet (page 1 like the Lua; «runs» instead of «flights»), from 0.7.2 for Heli (own top bar with clock and profile/rate). From 0.7.3 also for Glider (own colours, square boxes; the full screen is scaled from the compact view below the top bar). Gas Engine follows; until then Gas Engine still starts with an empty full-screen view.
  • Arrange automatically (from 0.4.0): one click makes all gaps between the boxes and to the edge equal and fills the area. What is beside and below what stays. Next to it the mode: Equal width per row (default: side by side equally wide, rows keep their height ratio), Keep proportions (everything stretched in the old proportions), Distribute only (sizes stay, every gap is exactly the gap setting, the remaining space is shared evenly at the edges; if the boxes are closer, the studio uses the largest gap that fits) and New grid (all boxes in reading order in an even grid, for badly scattered layouts). Gap: default 8 px in full screen, 5 px in the compact view, selectable 4–10 px. Areas the Lua draws itself stay free; the column with such an area keeps its width. If a box would become too small or the boxes interlock, the studio changes nothing and says why. Undo takes the arrangement back. Decorations stay where they are. From 0.4.1, with «New grid» the boxes of the last row fill the free space of that row, also next to an area of the Lua such as «Flights».

Symbols, unit and decoration (from 0.3.0)

Only with a Lua version that supports Lua-Studio format 2. Otherwise the studio shows a note and writes format 1.

  • Symbol per box: top left in front of the title, coloured like the value (normal, warning, alarm). Size 24, 32, 48 or 64 px (on the X18RS; scaled down on X14 and X18). Tow only from 48 px.
  • Unit: next to the value (as before), bold top left or none. Voltage, current, consumption, energy, RPM and throttle deliberately have no picture but the bold unit.
  • Unused symbols (from 0.4.1): if no studio file on the radio names a symbol any more, the «Transfer» tab shows «Delete n unused symbols …» beforehand («Which files?» expands all names). They are deleted only if you tick the box, and only those files. Without the tick they stay on the SD card and do no harm.
  • Decoration: + Symbol, + Text, + Line, + Frame places free elements without a value, at most 24 per view, below the boxes. Drag to move; position, size and colour on the right; Delete removes.
  • Preset sets the layout to the Lua's look («Lua default» or the Lua's templates). New models start with the template «Original» where Lua-Studio has one; to change it, delete or move boxes. Limits and settings stay.

Radio quick test (from 0.3.1)

After a transfer to a connected radio the studio checks by itself after a few seconds, once the radio has reloaded the model. With a connected radio you can press Radio quick test in the «Transfer» tab at any time (not available for SD drive and folder). It reads the Lua's info file and the radio's Lua log and reports:

  • whether the Lua loaded the studio file and whether it found invalid fields;
  • whether the Lua supports the format and found sensors;
  • notable log lines, e.g. Lua errors, instruction limit, memory or missing symbols;
  • whether the radio shows the changed view at all (otherwise you will see no change there).

If it says «Info file not rewritten since the transfer», switch the model on the radio once and test again.

Size guard

The size guard at the bottom shows file, elements, tables, estimated Lua memory when loading, boxes, graphs, lists, decoration, symbols and bitmap memory, each with a traffic light. A red line blocks the transfer and states the reason.

Limits & settings

  • Limits apply per value for the whole model, no matter in which box the value is. New models start with the Lua's factory limits. An empty field switches that level off; if both are empty, the radio uses the factory limit (completely off only with Off); «factory: …» only shows for values without an entry yet. Off switches an alarm off completely. For own sensors «Alarm when» must be chosen, and with «below» the alarm must be lower than the warning (with «above» higher) – otherwise the studio does not transfer.
  • Also with motor off (from 0.4.1, only for Luas that support it): ticked (default), the alarm also sounds while the motor switch (e.g. SF) is off. Untick it and this alarm stays silent while the motor is off; the Studio then shows a yellow band listing all such alarms. «all» ticks or unticks every alarm. Error codes and shutdown reasons always sound and have no tick box. If the Lua on the radio does not know this setting yet, the alarm still sounds there; the band says so.
  • Adjust values: factor, offset, unit and decimals of a value, e.g. RPM ÷ 2. Applies everywhere, also to the limits.
  • Settings of the Lua, e.g. battery and capacity.
  • Template: load «Lua default» or an own template; Save as template; From model copies everything from another model.

Everything is saved on the PC automatically.

Transfer

  1. Tab Transfer, then Transfer to the radio.
  2. The studio checks the file, backs up the old file on the PC, writes the new one, reads it back and compares. With a connected radio it reloads the model; otherwise switch the model on the radio once.
  3. If you changed something in the widget menu on the radio, the studio shows the changes and takes them over when the box is ticked. Without the tick they keep applying on the radio on top of the new file.
  4. If you only changed a view the Lua does not show on the radio right now (e.g. compact while the radio shows full screen), the studio asks before transferring.
  5. If two models have names that differ only in upper/lower case, the studio blocks the transfer (they would share the file): rename one model.

Backups are in the Lua-Studio user folder under Studio/sicherungen (Mac: ~/Library/Application Support/Lua-Studio, Windows: %APPDATA%\Lua-Studio).

Prepare without a radio (from 0.3.0)

  1. + Prepare at the top (or + Prepare a new model on the start page). As before, this also works with source «Prepared (without radio)», Load models, then Prepare new model …
  2. Enter the display group, the Lua and the model name exactly as on the radio. The studio shows the identifier the radio uses for the file.
  3. Design as usual. Own sensors are only available after the first connection; the Lua's values work right away.
  4. In Transfer choose an SD drive (card reader or radio as drive) or a folder. The studio writes to scripts/studio/ and writes nothing if the same identifier exists there with different case.
  5. Later with the radio: open the radio's model, tab «Limits & settings», choose the matching entry under Prepared and Apply. The model list shows «prepared layout available» when the identifier matches.
  6. The × in the list moves a prepared model to the trash.

7. Known limitations

  • Picture rate: about 25 frames per second, measured on a Mac with the X18RS. The connection on Windows has not been measured with a real radio yet.
  • Tested on real hardware only with the X18RS, Ethos 26.2.0, on a Mac. Other radios and the connection on Windows are not yet tested with a real radio.
  • The programs are not signed (see chapter 3).
  • While Lua-Studio is connected, no other program (e.g. the FrSky Suite) can use the serial connection.

9. Reporting a problem (from 0.3.3)

Lua-Studio keeps an error log of what happens: start (version, operating system), connecting and disconnecting, loading models, every step of a transfer, the radio quick test, blocks by the size guard and every error with the place in the program. That way a crash can be found afterwards.

  1. When something goes wrong: keep Lua-Studio open (or start it again) and, if possible, keep the radio connected.
  2. Top right: Help ▾ → Error log … (on the Mac also in the menu bar under “Help”).
  3. Choose Save for support (ZIP) …. Suggested: desktop, name “Lua-Studio Fehlerprotokoll <date>.zip”.
  4. Send the ZIP file by mail or messenger, with a short note: what you did and what happened.

What the ZIP contains: the log (lua-studio.log, lua-studio-alt.log), system.txt (versions of Lua-Studio, operating system, radio). With a connected radio also the last 400 lines of the radio's Lua log and the info files of the Luas (*.info.json). Not included: studio projects, model files, serial numbers. The user folder is replaced by ~ everywhere. But: the info files list the models on the radio with model name, model location (including folder name) and sensor list (name, AppID, physical ID). This is needed to match the entries; if you do not want to pass it on, look at the ZIP first.

Levels: normal (default) records the events and all errors. verbose also records every command sent to the radio (shortened) and the radio's whole Lua log; only switch it on when asked to, then trigger the problem again. off records nothing, not even errors.

Location: Mac ~/Library/Application Support/Lua-Studio/Protokoll, Windows %APPDATA%\Lua-Studio\Protokoll (button Open folder). At most two files of 1 MB each; when the current one is full it becomes the old one and the previous old one is dropped. Delete empties the log.

With a GitHub account you can also report it as an issue with the Fehler / Bug template and attach the ZIP.
